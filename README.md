# 城市统计片区重划分摊服务

把旧网格（带整数户数的整数矩形）按矩形重叠面积，均匀估算分摊到新的统计片区，
用于跨年对比。FastAPI + SQLite 实现，支持整版版本提交、异步生成、快照隔离与原子发布。
另提供**外部核定供数**能力：整版提交每个片区的非负整数核定户数，用整数最大流判定
它与已发布旧网格是否相容，相容时保存逐格整数流向，不可行时给出受限旧格、可达片区与缺额。

## 业务规则

- 矩形为整数轴对齐矩形 `[x1, y1, x2, y2]`，要求 `x1 < x2`、`y1 < y2`，面积 `(x2-x1)*(y2-y1)`。
- 每次**整版提交**旧网格或新片区，每版最多 **12** 个条目；同版条目编号唯一、矩形**内部不得重叠**（边界相接允许）。
- 生成结果时，**任一旧格未被新片区完整覆盖则拒绝**该次生成；片区可以延伸到旧网格之外。
- 通过覆盖校验后，**逐格**按重叠面积分摊该旧格的整数户数：
  - 先按面积比例取整；
  - 余数用**最大余数法**分配，余数相同时按**片区编号升序**（可解析为整数的编号按数值升序，否则按字符串升序）。
- 分摊结果**总户数守恒**，并带守恒护栏；输出片区汇总及两份输入版本。
- 生成在后台串行执行。生成任务在创建的同一事务内**固定当时最新的 old/new 版本快照**，
  生成期间仍可替换任一输入（产生新版本），不影响进行中的任务。
- 当前结果在单事务内原子切换；新结果**完整发布前**，`/result` 始终返回上一份已发布结果；
  生成失败只标记任务，**不改变**已发布结果。

### 外部核定供数

- `POST /verifications` **整版提交**每个片区的非负整数核定户数；核定记录绑定读取时刻的
  **当前已发布生成任务**及其两份输入版本（old/new 版本号一并落库）。
- 旧格的户数只能分给与其矩形**面积相交**的片区（只看是否相交，不沿用原来的面积比例）；
  该运输问题用整数容量最大流（Dinic）求解，容量与流量均为整数：
  - **相容**（最大流 = 总户数）：保存逐格 -> 逐片区的整数流向，旧格侧合计等于原户数、
    片区侧合计等于核定值（两侧合计分别吻合），并在同一事务把该核定切换为当前有效核定；
  - **总量相同却不可行**：返回 HTTP 422 与结构化诊断——受限旧格（残余网络中源点可达的
    旧格）、可达片区（这些旧格能到达的片区）、缺额（总户数 − 最大流，即最小割见证）；
    失败记录留痕但**不覆盖**旧有效核定；
  - **编号集合不符**（缺编号/未知编号）或**总户数不符**：返回 400 并说明差异，不落任何记录；
  - 尚无已发布生成任务时返回 409。
- `GET /verifications/current` 只返回与**当前已发布任务**对应的有效核定；生成任务切换后，
  旧核定不会被当成新任务的结果（返回 404，需按新任务重新核定）。
- 核定供数完全独立于分摊与发布流程：**`/result` 行为保持不变**，核定失败不影响已发布结果。

## 目录结构

```
app/
  config.py       运行配置（DB 路径、每版上限）
  models.py       Pydantic 请求/响应模型
  allocation.py   纯函数：几何、覆盖校验、最大余数法分摊、汇总
  flow.py         纯函数：Dinic 整数最大流、相容性判定与不可行诊断
  db.py           SQLite 持久化、版本快照、后台生成与原子发布、核定供数
  main.py         FastAPI 路由与单线程后台工作池
tests/            pytest 单元 + 集成测试（41 个用例）
Dockerfile
docker-compose.yml
```

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/old-grids` | 整版提交旧网格（编号、矩形、户数），产生不可变版本 |
| POST | `/new-districts` | 整版提交新片区（编号、矩形），产生不可变版本 |
| GET | `/versions?kind=old\|new` | 列出输入版本（历史版本保留） |
| GET | `/versions/{id}` | 查询单个版本 |
| POST | `/generations` | 开始生成（202），同步固定版本快照，后台计算 |
| GET | `/generations` | 列出全部生成任务 |
| GET | `/generations/{id}` | 查询任务状态：pending/running/succeeded/failed |
| GET | `/result` | 当前已发布结果（片区汇总 + 两份输入版本），无结果时 404 |
| POST | `/verifications` | 整版提交片区核定户数：201 相容 / 422 不可行诊断 / 400 编号或总量不符 / 409 无发布任务 |
| GET | `/verifications/current` | 当前已发布任务对应的有效核定，无则 404 |
| GET | `/verifications/{id}` | 查询单次核定提交（含 infeasible 留痕记录） |
| GET | `/verifications` | 列出全部核定提交（含失败留痕） |
| GET | `/health` | 健康检查 |

## /docs 演示流程

1. `POST /old-grids` 提交旧网格；
2. `POST /new-districts` 提交新片区；
3. `POST /generations` 触发生成，记录返回的任务 `id`；
4. 轮询 `GET /generations/{id}` 直到 `succeeded`（覆盖不足时为 `failed`，`error` 给出原因）；
5. `GET /result` 查看片区汇总、逐格分摊明细与两份输入版本。

### 请求示例

```json
// POST /old-grids
{
  "items": [
    {"id": "g1", "rect": [0, 0, 10, 10], "households": 7},
    {"id": "g2", "rect": [0, 10, 10, 20], "households": 11}
  ]
}
```

```json
// POST /new-districts（rect 也可写成 {"x1":..,"y1":..,"x2":..,"y2":..} 对象）
{
  "items": [
    {"id": "d1", "rect": [0, 0, 5, 20]},
    {"id": "d2", "rect": [5, 0, 10, 20]}
  ]
}
```

上例两个旧格在 d1/d2 上均为等面积（各 50%）：
`g1=7` 拆成 `4/3`、`g2=11` 拆成 `6/5`（余数并列时编号小的 d1 先得 +1），
片区汇总 `d1=10`、`d2=8`，总计 18，与输入总户数一致。

## 核定供数演示

先按上面的流程生成并发布，再提交整版核定户数：

```json
// POST /verifications（编号须覆盖当前任务全部片区，总户数须等于旧网格总户数）
{
  "items": [
    {"id": "d1", "households": 10},
    {"id": "d2", "households": 8}
  ]
}
```

- 相容时返回 201，`flows` 为逐格整数流向，`old_totals`/`district_totals`
  分别给出两侧合计以便核对；随后 `GET /verifications/current` 即可读取有效核定。
- 若总量相同却无法只沿相交关系分摊，返回 422，`detail` 形如：

```json
{
  "message": "核定总户数与旧网格总户数相同，但旧格户数无法只沿面积相交的片区整数分摊到各片区核定值",
  "verification_id": 2,
  "generation_id": 1,
  "old_version": 1,
  "new_version": 2,
  "total_households": 10,
  "blocked_old_ids": ["g1"],
  "reachable_district_ids": ["d1", "d3"],
  "shortfall": 3
}
```

含义：受限旧格 `g1` 的户数只能送进可达片区 `d1/d3`，而这些片区的核定容量之和
比 `g1` 的户数少 3（缺额）。该失败记录可经 `GET /verifications/2` 追溯，但不会替换
此前的有效核定。

## 测试

```bash
pip install -r requirements.txt pytest httpx
pytest -v
```

覆盖要点：矩形几何与重叠、整版数量/编号/内部重叠校验、覆盖不足拒绝、
最大余数法与编号并列规则、零户数与多格守恒、片区延伸/零分摊片区、
快照固定与生成期间交错替换、失败不影响旧发布结果、串行任务各自快照、版本不可变；
核定供数侧覆盖整数最大流守恒与确定性、不按面积比例的自由分配、
局部冲突的受限旧格/可达片区/缺额诊断（含独立回溯判定器的 200 组随机交叉验证）、
零户数/零需求边界、失败不覆盖旧核定、编号/总量不符拒绝、发布交错后旧核定失效、
以及 `/result` 行为不受核定影响。
